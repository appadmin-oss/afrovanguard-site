# Tasks — audit fixes, 2 November 2026

Scope: the task feature — `lib/Collab.php`, `lib/TaskMatch.php`,
`lib/TaskLedger.php`, `lib/TaskReport.php`, `integrations/cacentre-tasks.php`,
`portal/collab.php`, `portal/chat.php` — and the DDL path every runtime table
goes through (`Database::translateDDL`). Fixed on branch
`claude/stoic-hamilton-1f18hh`.

## What the audit found

| | Finding | Severity |
|---|---|---|
| T1 | `collab_tasks` (and ~90 other runtime tables) never created on MySQL 8: `TEXT NOT NULL DEFAULT ''` is error 1101 there, and `translateDDL()` passed it through. A fresh MySQL 8 deploy aborted outright on `db/schema.mysql.sql`. MariaDB accepts it, which is how every earlier validation passed. | **Critical** |
| T2 | The cron auto-assign sweep overwrote a member's claim made while it was scoring, and two overlapping ticks could both assign one task. | **High** |
| T3 | CACENTRE sends `toggle` meaning "mark done"; this door flips, so a retried tick reopened finished work. | **High** (cross-site) |
| T4 | `task_add` / chat `assign`: any signed-in learner could create a task — with a notification and an email of their own text — for any user id. | Medium |
| T5 | `deleteTask` did not resync the goal, and let a creator delete a task its assignee had finished, erasing it from their record. | Medium |
| T6 | `TaskLedger`'s index ran `CREATE INDEX IF NOT EXISTS` outside `execSchema`, so on MySQL it failed silently and never existed. | Low |
| T7 | Overdue (portal, matcher) and on-time (ledger) used UTC days while the report and reminders use Lagos. | Low |

## What this branch fixed

- **T1** — `translateDDL()` writes a literal TEXT/BLOB default as an expression, `DEFAULT ('')`, on MySQL (type kept); three raw ALTERs go through `execSchema`; `db/schema.mysql.sql` wrapped in place; `docs/db-portability.md` corrected. Held by `tests/ddltextdefault.test.php` (sweeps every CREATE/ALTER in `lib/` and the schema files) and `tests/mysql.test.php` (creates such a table on a real server).
- **T2** — in auto mode `assignTask` updates only `WHERE assignee_id = 0 AND done = 0` and stops (no notice, no ledger row) when that changes nothing; each tick claims a task by compare-and-set on `auto_assigned_at` before scoring it. Held by `tests/todo.test.php` ("sweep race").
- **T3** — new `done` action: `Collab::completeTask()`, idempotent by compare-and-set, answering `{ok:true, done:true}`; `toggle` unchanged. The `CacWeek::changed` call back to CACENTRE is held until the answer is written (and finished, on FPM/LiteSpeed). Held by `tests/cactasksdone.test.php` (the real door over loopback HTTP).
- **T4** — `addTask()` requires `$mayAllocate` and an active assignee before a task goes to anybody but its creator; `Collab::mayAllocate()` is the one rule both doors use. Held by `tests/taskadd.test.php`.
- **T5** — a finished task assigned to somebody else cannot be deleted (409 with the reason); a deleted goal step resyncs its goal. Held by `tests/taskdelete.test.php`.
- **T6** — the index goes through `execSchema`. Held by `tests/mysql.test.php` (index present on MySQL 8) and `tests/taskledger.test.php`.
- **T7** — all three read `TaskReport::today()`. Held by `tests/tasktz.test.php`, pinned to 23:30 UTC.

Every test above was seen to fail before its fix, and the key rules were
mutation-checked (fix removed, test fails, fix restored).

## Still open

- **The tasks door's token is replayable inside its minute, and the POST body
  is not signed** — the token names the member, not the action. With `done`
  idempotent a replayed tick is now harmless; `toggle` and `update` are not.
  Recommended: bind a nonce (or a hash of the body) into the token and refuse
  a nonce seen twice, then retire `toggle` once CACENTRE sends `done`
  everywhere.
- **Other bare `->exec('CREATE INDEX IF NOT EXISTS …')` calls** (ChatBot,
  GoalTrack, Commitments, AiOps, DiaryRepository, MemberDesk, AvRouter,
  Birthdays) have T6's shape; each needs checking for a SQLite-only guard
  before moving it to `execSchema`.
- **TEXT columns in an index without a prefix length** (error 1170 on MySQL):
  `auth_illustrations.schedule_kind`, `diary_entries.entry_date` (runtime DDL),
  `ngv_applications.status` / `email`. A different class from T1, found by the
  same MySQL 8 sweep.
- The callback deferral (T3) only shortens the wait on FPM or LiteSpeed; under
  mod_php the call still runs before the connection closes, as before.

## Deploy order

**Deploy this site before CACENTRE's change that sends `done`.** An older
build of this door answers `done` with 400 `unknown-action`, so a CACENTRE
that sends it first would have every tick refused. `toggle` keeps working, so
deploying this site first is safe for the CACENTRE currently live.
