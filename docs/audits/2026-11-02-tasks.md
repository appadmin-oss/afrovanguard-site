# Tasks — audit fixes, 2 November 2026

Scope: the task feature — `lib/Collab.php`, `lib/TaskMatch.php`,
`lib/TaskLedger.php`, `lib/TaskReport.php`, `integrations/cacentre-tasks.php`,
`portal/collab.php`, `portal/chat.php` — and the DDL path every runtime table
goes through (`Database::translateDDL`). Fixed on branch
`claude/stoic-hamilton-1f18hh`.

## What the audit found

| | Finding | Severity |
|---|---|---|
| T1 | `collab_tasks` (and ~90 other runtime tables) never created on MySQL 8: `TEXT NOT NULL DEFAULT ''` is error 1101 there, and `translateDDL()` passed it through. A fresh MySQL 8 deploy aborted outright on `db/schema.mysql.sql`. MariaDB accepts it, which is how every earlier validation passed. | **Critical** |
| T2 | The cron auto-assign sweep overwrote a member's claim made while it was scoring, and two overlapping ticks could both assign one task. | **High** |
| T3 | CACENTRE sends `toggle` meaning "mark done"; this door flips, so a retried tick reopened finished work. | **High** (cross-site) |
| T4 | `task_add` / chat `assign`: any signed-in learner could create a task — with a notification and an email of their own text — for any user id. | Medium |
| T5 | `deleteTask` did not resync the goal, and let a creator delete a task its assignee had finished, erasing it from their record. | Medium |
| T6 | `TaskLedger`'s index ran `CREATE INDEX IF NOT EXISTS` outside `execSchema`, so on MySQL it failed silently and never existed. | Low |
| T7 | Overdue (portal, matcher) and on-time (ledger) used UTC days while the report and reminders use Lagos. | Low |

## What this branch fixed

- **T1** — `translateDDL()` writes a literal TEXT/BLOB default as an expression, `DEFAULT ('')`, on MySQL (type kept); three raw ALTERs go through `execSchema`; `db/schema.mysql.sql` wrapped in place; `docs/db-portability.md` corrected. Held by `tests/ddltextdefault.test.php` (sweeps every CREATE/ALTER in `lib/` and the schema files) and `tests/mysql.test.php` (creates such a table on a real server).
- **T2** — in auto mode `assignTask` updates only `WHERE assignee_id = 0 AND done = 0` and stops (no notice, no ledger row) when that changes nothing; each tick claims a task by compare-and-set on `auto_assigned_at` before scoring it. Held by `tests/todo.test.php` ("sweep race").
- **T3** — new `done` action: `Collab::completeTask()`, idempotent by compare-and-set, answering `{ok:true, done:true}`; `toggle` unchanged. The `CacWeek::changed` call back to CACENTRE is held until the answer is written (and finished, on FPM/LiteSpeed). Held by `tests/cactasksdone.test.php` (the real door over loopback HTTP).
- **T4** — `addTask()` requires `$mayAllocate` and an active assignee before a task goes to anybody but its creator; `Collab::mayAllocate()` is the one rule both doors use. Held by `tests/taskadd.test.php`.
- **T5** — a finished task assigned to somebody else cannot be deleted (409 with the reason); a deleted goal step resyncs its goal. Held by `tests/taskdelete.test.php`.
- **T6** — the index goes through `execSchema`. Held by `tests/mysql.test.php` (index present on MySQL 8) and `tests/taskledger.test.php`.
- **T7** — all three read `TaskReport::today()`. Held by `tests/tasktz.test.php`, pinned to 23:30 UTC.

Every test above was seen to fail before its fix, and the key rules were
mutation-checked (fix removed, test fails, fix restored).

## Still open

- **The tasks door's token is replayable inside its minute, and the POST body
  is not signed** — the token names the member, not the action. With `done`
  idempotent a replayed tick is now harmless; `toggle` and `update` are not.
  Recommended: bind a nonce (or a hash of the body) into the token and refuse
  a nonce seen twice, then retire `toggle` once CACENTRE sends `done`
  everywhere.
- **Other bare `->exec('CREATE INDEX IF NOT EXISTS …')` calls** (ChatBot,
  GoalTrack, Commitments, AiOps, DiaryRepository, MemberDesk, AvRouter,
  Birthdays) have T6's shape; each needs checking for a SQLite-only guard
  before moving it to `execSchema`.
- **TEXT columns in an index without a prefix length** (error 1170 on MySQL):
  `auth_illustrations.schedule_kind`, `diary_entries.entry_date` (runtime DDL),
  `ngv_applications.status` / `email`. A different class from T1, found by the
  same MySQL 8 sweep.
- The callback deferral (T3) only shortens the wait on FPM or LiteSpeed; under
  mod_php the call still runs before the connection closes, as before.

## Deploy order

**Deploy this site before CACENTRE's change that sends `done`.** An older
build of this door answers `done` with 400 `unknown-action`, so a CACENTRE
that sends it first would have every tick refused. `toggle` keeps working, so
deploying this site first is safe for the CACENTRE currently live.

## Addendum, 19 November 2026 — tasks people finish

The audit above made tasks correct; this makes them get done. Modelled on
CACENTRE's Goalspace: one owner, a date, proof, accept-or-decline with a
reason, escalation up the line. Merged first with
`origin/claude/finme-dues-training-fees-l54o5j` (a fast-forward).

| | Change | Where |
|---|---|---|
| A | A task can say what "done" looks like (`outcome`). The add form offers it, and asks for it once — never forces it — when the task goes to somebody else or is sized L. Shown on the task and in the notices. | `Collab::addTask`, `portal/views/tasks.php`, `tasks.js askOutcome` |
| B | The first date (`first_due`) and the agreed date (`agreed_due`) are kept. The person holding a task somebody else gave them must give a reason to move its date; the move is logged in `task_due_changes` (who, when, from, to, why) and the giver is told. The giver re-dating it, or agreeing to a proposed date, is the new agreement. On time — in `TaskLedger::history` (and so `TaskMatch` scoring) and in `TaskReport` — is measured against the agreed date (`TaskLedger::agreedDue`). | `Collab::updateTask`, `TaskLedger` |
| C | Work given to somebody arrives "waiting for you" (`accept_state`): Accept · Propose a date (the giver agrees or keeps theirs) · Can't, because… with a reason from `TaskLedger::REASONS` — one list shared with handing back: busy, unclear, blocked, not mine, deprioritised (and "something else"). Waiting work is not counted as theirs until accepted. Time from given to accepted is kept (`accepted_at`, `history()['accept_hours']`). Your own tasks skip the step. Planner (AI) and sweep steps arrive `proposed`; declined, they go back to the pool; a person's request declined goes back to the giver. Ticking it done accepts it on the way. | `Collab::acceptTask/proposeDate/answerDate/declineTask` |
| D | Finishing a task somebody gave you tells them, with Thanks / Send back (a reason; the task reopens). | `Collab::setDone/thankTask/sendBack` |
| E | One escalation ladder, `TaskLedger::ladder()`, for tasks and meeting commitments: the owner on the due day and the day after; on day 3 the giver (for a commitment, the meeting's chair, the session's mentor, or whoever filed a chat promise) with reassign / new date / drop; after that one weekly roll-up on Mondays. Each step fires only on its day and once (dedupe key per step and date) from the existing web cron. It replaces the daily "Overdue task" notice and the daily commitment nudge. The evening report goes to the people who gave out the late work — each about their own — instead of every coordinator. | `TaskLedger::chaseAll`, `Notifications::dispatchDue`, `Commitments::sweepOverdue/ladderItems/setDue`, `TaskReport::recipients/sendIfDue` |
| F | The Tasks page leads with "Everything you owe" (Overdue / Today / This week / Waiting on you), merged in the browser from what the page already loads — My tasks, what waits on your answer, commitments, Goalspace, the CACENTRE week and console tasks. No new cross-site request. "My tasks" is the first card. | `tasks.js renderOwe`, `commitments.js`/`goalspace.js` (`av:owe`) |
| G | A tick on a bad connection is kept on the device, retried (on `online` and every 30s), and the person is told. The tick is sent as a state to an idempotent door (`task_done`), so a retry cannot flip it back. | `tasks.js AvTaskKit.tickQueue`, `Collab::setTaskDone` |

Held by `tests/taskflow.test.php` (68 assertions; it executes the page's
rules in node when node is installed). It was run before the change and
failed (fatal on the missing `outcome` parameter, the first of the new
calls). Mutation-checked — each rule removed, the test failed, the rule
restored: on time against the agreed date (ledger and report), a move needs
a reason, a move tells the giver, waiting work is not "mine", AI steps
arrive proposed, the ladder fires only on its day, the ladder fires once,
the report goes only to givers of late work, the done notice, and the kept
tick. Checked on MySQL 8.0.46: the new columns, `task_due_changes` and its
index are created, and the add → move → accept → counter → decline → done →
thanks → ladder → report path runs.

Three existing tests changed with the behaviour they pinned: a given task is
"waiting" until accepted (`taskassign`), the commitment chase is the ladder
(`commitments`), and the evening report goes to givers (`taskreport`).

### Not done

- The CACENTRE bridge's `update` passes a `reason` and refuses
  `reason-required` (422) when one is missing; CACENTRE's own UI does not
  yet send one, so a member moving a given task's date from CACENTRE is
  refused until it does.
- "Propose a date", "Move date" and "Send back" ask with `prompt()`, as the
  existing "blocked" control does; an inline form would be kinder.
- A task's date-change log is kept and readable (`TaskLedger::dueChanges`)
  but not yet drawn on the task.
